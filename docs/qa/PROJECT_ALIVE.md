## Platform research

- Material distinguishes spatial springs from effects. Use directional movement and restrained overshoot on spatial surfaces, and coordinated opacity without bounce. Apple calls for immediate and cancellable tactile feedback and a stable reference during motion. [Material 3 motion physics](https://m3.material.io/styles/motion) · [Apple HIG motion](https://developer.apple.com/design/human-interface-guidelines/motion)
- Motion's imperative animation can drive retained DOM without React rendering each frame. Presence solves exit preservation. Layout and LayoutGroup solve selective continuity and synchronize measurements. Motion values are suitable for direct gesture progress, and spring transitions can accept velocity. useAnimate scopes lifetime to a component. Validate each feature under measured conditions before expanding usage. [Presence](https://motion.dev/docs/react-animate-presence) · [Layout and shared elements](https://motion.dev/docs/react-layout-animations) · [LayoutGroup](https://motion.dev/docs/react-layout-group) · [Motion values](https://motion.dev/docs/react-motion-value) · [Springs](https://motion.dev/docs/react-transitions) · [Gestures](https://motion.dev/docs/react-gestures) · [useAnimate](https://motion.dev/docs/react-use-animate)
- WAAPI is already available in Chromium and provides a small native path to compositor animation. Its API allows explicit cancellation and completion, while choreographing multiple live surfaces and deriving spring keyframes are application responsibilities here. View Transitions can coordinate captured states, but introduce snapshot ownership, compatibility gating and a less direct fit for finger-driven live surfaces. [Web Animations](https://developer.mozilla.org/en-US/docs/Web/API/Web_Animations_API) · [View Transitions](https://developer.mozilla.org/en-US/docs/Web/API/View_Transition_API)
- Limit animated navigation to transform and opacity, avoid permanent promoted layers, and use a bounded rAF recording and DevTools traces to study missed frames. Secure native capture may redact the UI while browser software rendering can still demonstrate choreography with fictional data. Keep the existing secure-window policy and verify Android separately. [Compositing](https://developer.chrome.com/blog/inside-browser-part3) · [Performance profiler](https://developer.chrome.com/docs/devtools/performance/reference) · [Android WebView debugging](https://developer.chrome.com/docs/devtools/remote-debugging/webviews) · [Android WebView memory](https://developer.android.com/develop/ui/views/layout/webapps/manage-webview-memory)
- Rive and Lottie have MIT-licensed web runtimes. Rive's compiled assets and state machine runtime make sense for interactive artwork. Lottie makes sense for authored timeline assets and adds a rendering runtime. Simple original, event-driven SVG paths avoid both dependencies and stay usable offline. [Rive state machines](https://rive.app/docs/runtimes/state-machines) · [Rive web runtime](https://github.com/rive-app/rive-wasm) · [Lottie web](https://github.com/airbnb/lottie-web)
- Follow the OS preference at initialization and while running. Reduced motion uses state, focus and copy to communicate the result, with position changes suppressed. [WCAG animation from interactions](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)

## First controlled production-bundle comparison

The test fixture used Edge 157 headless, 390 × 844 CSS pixels, 1× device pixel ratio, light theme, Silky, and system motion enabled. The compiled baseline and candidate use the same app workflows and a disposable synthetic dataset. Profile's full-width movement is present on the compiled baseline. The visual differences on opening are timing and continuity. Subpage motion improved more clearly.

| Interaction | Motion 3.0 | Project Alive prototype |
| --- | --- | --- |
| Primary tabs | 14 px arrival | 52 px arrival and 36 px departure, with a travelling selection indicator |
| Create Task | 12 px vertical entrance, immediate removal | 390 px horizontal entrance and reverse dismissal |
| Add details | Browser feature-gated native summary layout | Continuous grid reveal with inert closed fields |
| Task completion | Native checkbox and list regroup | A drawn glyph in the real Completed row |
| Profile / Appearance | Full-width Profile entrance, 16 px submenu | Full-width spring entrance, 42 px submenu |
| Money / Scheduled | 16 px arrival | 46 px arrival |
| Recurring item | Opens the existing edit view | Same existing edit view in this comparison |

The first compiled pair captured between 4 and 34 compositor images per interaction. Most frame intervals were around 16.7 ms. The first Today to Money trial had a p95 interval of 66.6 ms on the baseline and 116.8 ms on the prototype. The prototype reduced the worst observed composer frame gap from the Vite development run, although the production composer still had frame gaps. These short runs have substantial sensitivity to cold JS, rasterization, the host, and the capture workload. The primary tab opening had no observed layout shifts in either compiled build. Advanced disclosure intentionally moved surrounding content and generated input-related shifts.

The candidate added 167,547 minified bytes to the largest application JS chunk in this experiment. Motion is MIT-licensed. The chart chunk remained a separately loaded 416,085 bytes. No native battery or memory conclusions follow from this browser fixture.
