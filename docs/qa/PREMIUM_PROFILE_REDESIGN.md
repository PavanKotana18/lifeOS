## Verification boundaries

Render the baseline and candidate with `tests/browser/profile-notification-centre.cjs` on separate Vite starts. Set `LIFEOS_PREMIUM_PROFILE=1` for candidate-only paths. The browser uses isolated synthetic authentication and storage; it cannot prove that Android posted a reminder, handed a scoped file-provider result back or preserved a biometric session.

Visual evidence excludes secrets and uses the existing reduced-motion override. The short-height name-entry screenshot represents the viewport after a keyboard reduces available height. Android IME behavior, keystore authentication and process-death behavior remain physical-device gates.

## Visual review results

The rejected baseline was captured before editing. The candidate review compared the same destinations in light and dark themes, including important bottom sheets and full-screen readers. Checks included typography, alignment, viewport gutters, icon proportions, text wrapping, contrast, information hierarchy, and controls over the 320, 360, 393 and 430 CSS-pixel browser viewports. At 125% root font size the 47-character synthetic name wrapped within the identity panel. Name entry remained reachable in a short simulated keyboard viewport.

The first review found repetitive large palette cards and an offscreen Apply action. The candidate uses compact palette choices and focuses the representative preview when a palette is selected. Visual review also found broken relative asset paths in About and the license reader in the nested browser harness. Both now use the app's asset root. The final browser checks require a decoded approved icon and the bundled license heading, and wait for the draft library to render before capture.
