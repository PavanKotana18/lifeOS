# PR #36 Keystore setup failure

## Diagnosis

The physical Android 16 report could not be reproduced in this session: `adb devices -l` found no attached device, and the available hosted emulator workflow does not drive a real device-credential prompt. The prior generic native rejection also discarded the underlying exception.

The source contains a concrete failure path for the reported Android 16/API 36 setup. New API 30+ keys use a time-bound biometric/device-credential policy. Setup initialized an AES-GCM `Cipher` before asking the user to authenticate. Android documents that initialization of a time-bound authentication key can throw `UserNotAuthenticatedException` until authentication succeeds. The old catch converted every such failure to “Unable to initialize Android Keystore.” This path affects fresh setup and interrupted setup retry when the device-credential-window policy is selected.

## Correction

Credential-window operations now show the native prompt first and create a fresh `Cipher` after successful authentication. The change covers initial setup, unlock and recovery rebind. Per-use strong-biometric keys keep their existing `CryptoObject` flow. Existing aliases, wrapped database keys and recovery metadata are never deleted or regenerated by this correction.

Setup failures now log only the operation identifier, exception class and stack frames. Exception messages, key material, recovery codes, plaintext records and authentication tokens are not logged. The UI receives the operation and exception class with a safe retry message.

Interrupted first-time setup retains its durable pending marker and original alias. The opt-in Android authentication acceptance test now cancels the first setup prompt, verifies the resumable state and alias remain, then accepts a retry and verifies the alias remains in use. It refuses to run when a wrapper or alias already exists.

## Verification limits

The focused native source and onboarding tests pass locally. The Android acceptance test requires a dedicated fresh emulator/profile with an interactive system credential prompt; it was not run locally. CI emulator tests can compile and execute noninteractive native suites, but they do not verify this prompt flow. Physical Android 16 reproduction and acceptance remain pending. The captured exception type and stack from the reported phone remain unavailable.
